# Goal Spec — Agentic Python Tutor

> Defines *what* we're building and *why*. Fill this in first — the other specs should derive from it.

## 1. Problem Statement
<!-- What problem does this app solve? Who has this problem today, and how do they cope without this tool? -->
Self-taught Python learners (bootcamp students, CS beginners, career switchers) typically rely on generic MOOC courses or static tutorials that present the same fixed curriculum to everyone, regardless of their existing skill, pace, or the specific mistakes they make. When a learner gets stuck, they must self-diagnose why their code is wrong with no personalized guidance, and the course itself never adapts to skip what they already know or reinforce what they don't. This app uses a small team of specialized AI agents to build and continuously adapt a personalized Python curriculum per learner, generate level-appropriate explanations, grade coding exercises, and give both automated and conversational feedback.

## 2. Target Users
<!-- Who uses this app? e.g. solo travelers, families, groups of friends. Include any relevant personas. -->
Self-taught, beginner-to-intermediate Python learners who want a tutor-like, adaptive experience rather than a fixed, one-size-fits-all course — e.g. someone switching careers into tech, a bootcamp student supplementing coursework, or a CS student reinforcing fundamentals.

## 3. Core Use Cases
<!-- The primary user journeys, as short scenarios. e.g. "As a user, I want to create a trip and add destinations so that I can see my itinerary in one place." -->
- As a learner, I want to take a short diagnostic assessment so the system can gauge my current Python skill level per topic.
- As a learner, I want to receive a personalized curriculum that orders the Python topics I still need to learn.
- As a learner, I want each lesson to include an explanation pitched at my level and a coding exercise so I can practice immediately.
- As a learner, I want my code graded automatically against test cases and to receive qualitative code-review feedback, not just a pass/fail.
- As a learner, I want to ask a tutor questions about the current lesson when I'm stuck.
- As a learner, I want the curriculum to adapt — reinforcing topics I struggle with and advancing past ones I've mastered — so my time is spent efficiently.
- As a learner, I want to see my overall progress (mastery per topic) across my learning journey.

## 4. Core Features (MVP)
<!-- Bullet list of must-have features for v1. Be specific enough to scope work, not exhaustive. -->
- Responsive web application (usable on both desktop and mobile browsers — no native mobile app)
- Users can sign up (username + password) and log in
- A one-time diagnostic skill assessment (multiple-choice + short code questions) covering a fixed catalog of core Python topics
- A **Curriculum Planner Agent** builds an initial personalized topic sequence from the assessment results
- Lesson flow: a level-appropriate topic explanation (generated by the **Tutor Agent**) plus one coding exercise selected from a pre-authored exercise bank at the right difficulty
- An in-browser code editor with "Submit," which executes the learner's code against the exercise's test cases in a sandboxed runner
- An **Evaluator Agent** orchestrates sandboxed execution, interprets the test results, and computes a mastery-level change for the topic
- A **Code Reviewer Agent** gives qualitative feedback on the submission (style, structure, alternative approaches), independent of pass/fail
- The **Tutor Agent** also powers a per-lesson chat for the learner to ask questions about the current topic/exercise
- Adaptive progression: the curriculum advances, repeats, or inserts a remedial exercise based on the Evaluator's result
- A progress view showing mastery level per topic and topics completed

## 5. Nice-to-Have Features (Post-MVP)
<!-- Features explicitly deferred. Helps prevent scope creep. -->
- Support for languages other than Python (JavaScript, Java, etc.)
- Gamification (streaks, badges, leaderboards)
- Voice-based tutor interaction
- Peer/collaborative exercises
- Native mobile app
- Hardened per-execution sandbox (e.g. Firecracker/gVisor microVMs) replacing the MVP's resource-limited subprocess sandbox
- Retaking the assessment / re-diagnosing skill later in the journey

## 6. Out of Scope
<!-- Explicitly excluded from this project, to avoid ambiguity later. -->
- Support for programming languages other than Python
- AI-generated exercises or test cases — exercises and their test cases are pre-authored; only explanations, hints, and curriculum ordering are AI-personalized (see `backend-spec.md` §4 for rationale)
- Human tutor marketplace or live tutoring
- Payment/subscription billing

## 7. Success Metrics
<!-- How do we know this app is working? e.g. adoption, task completion, performance targets. -->
- A learner can sign up, complete the assessment, and receive a personalized curriculum
- A learner can complete a lesson: read an explanation, submit code, and receive both a pass/fail result and qualitative feedback
- A learner can ask the Tutor Agent a question and get a relevant reply
- The curriculum visibly adapts (advances or repeats a topic) based on submission outcomes
- A learner can view their mastery level per topic

## 8. Constraints & Assumptions
<!-- Budget, timeline, team size, must-use tech, offline requirements, target platforms (web/mobile), etc. -->
- Timeline: 2 weekends
- Team size: 1 person
- Target platform: Web only, built responsively so it also works on mobile browsers (no native mobile app)
- LLM provider: Anthropic Claude API powers all four agents
- Code execution: Python-only submissions, run in a resource-limited sandboxed subprocess — an accepted MVP trade-off, not hardened for public/untrusted use (see `backend-spec.md` §6)

## 9. Glossary
<!-- Domain terms specific to this app (e.g. "Trip", "Leg", "Itinerary item") and their precise meaning, to keep frontend/backend/API specs consistent. -->
| Term | Definition |
|------|------------|
| Learner | A person who has logged in and is working through a personalized Python curriculum. Referred to as "User" in the data model. |
| Skill Profile | A Learner's per-Topic mastery levels, seeded by the assessment and updated after every Evaluation. |
| Topic | A single Python concept unit in the fixed content catalog (e.g. "for loops," "list comprehensions," "classes & objects"). |
| Curriculum / Learning Path | The ordered, personalized sequence of Topics for a Learner, each with its own status (locked, current, completed). |
| Lesson | One instance of a Learner working through a Topic — its explanation plus a selected Exercise. |
| Exercise | A pre-authored coding challenge tied to a Topic, with a prompt, starter code, and test cases, at a given difficulty. |
| Submission | A Learner's code attempt for an Exercise within a Lesson. |
| Agent | One of four specialized AI roles — Curriculum Planner, Tutor, Code Reviewer, Evaluator — each with its own responsibility and context. |
| Evaluation | The pass/fail/partial result of running a Submission against an Exercise's test cases, plus the resulting mastery change. |
| Feedback | Qualitative, AI-generated commentary on a Submission (from the Code Reviewer Agent) or an answer to a learner's question (from the Tutor Agent). |
| Mastery Level | A per-Topic, per-Learner proficiency score (0–5) derived from Evaluations over time, used to decide curriculum progression. |
